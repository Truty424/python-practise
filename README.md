# python-practise

# Roadmap: Python → Backend → AI

The chapter order is deliberate. Every chapter ends with a deliverable — with a verification criterion for the mentor. GitHub repo from day one.

---

## 1. Environment

* Python 3.12+, `uv` (environments and packages)
* VS Code or PyCharm, ruff (lint + format)
* Git: commit, branch, merge, rebase, resolving conflicts
* GitHub: repo, PR, README
* Terminal: bash basics, environment variables, `.env`
* pytest: first test, fixtures, parametrize

**Task:** GitHub repo with `pyproject.toml`, ruff, pytest and CI (GitHub Actions). Three string functions (palindrome, word count, Caesar cipher) with tests. **Verification:** you clone it, run tests and lint, CI is green; live demo of branch → commit → rebase → merge.

## 2. Python — syntax and idioms

* Built-in types, mutable vs immutable
* Comprehensions (list, dict, set)
* Functions: `*args`, `**kwargs`, default arguments (the mutable-list trap), lambda
* Type hints, `Optional`, `Union`, generics, mypy
* Modules, packages, imports, `__init__.py`, `if __name__ == "__main__"`
* Exceptions: hierarchy, custom exceptions, `try/except/else/finally`
* f-strings, formatting
* Virtualenv vs global interpreter — why

**Task:** `todo` package with CLI: add / remove / list / mark done, JSON storage, custom exceptions, type hints. **Verification:** mypy clean; he explains why `def f(x=[])` is a trap and what happens on a circular `import`.

## 3. Files and formats

* Opening files: modes (`r`, `w`, `a`, `b`), `with`, encoding (UTF-8)
* Line by line vs whole file — large files
* `pathlib`: paths, creating directories, listing, glob
* `os`, `shutil`: copy, move, delete
* JSON: `json.load/dump`, serializing custom objects
* CSV: `csv.reader/DictReader`, Excel via `openpyxl`
* TOML / YAML — config files
* Binary files, `pickle` (and why not to trust it)
* Temporary files, atomic writes
* Command-line arguments: `sys.argv`, `argparse`

**Task:** Server log parser (e.g. nginx access log, 1 GB generated by a script): stats per status code, top 10 IPs, traffic per hour; output to CSV and JSON; CSV ↔ JSON ↔ TOML converter. **Verification:** the 1 GB file is processed without loading it all into memory; a malformed input file gives a readable error, not a traceback.

## 4. OOP

* Class, object, attribute, method, `self`, `__init__`
* Class vs instance attributes
* `@property`, `@classmethod`, `@staticmethod`
* Inheritance, `super()`, MRO
* Composition over inheritance — when
* Abstract classes (ABC), `Protocol` (duck typing)
* Dunder methods: `__repr__`, `__str__`, `__eq__`, `__hash__`, `__len__`, `__iter__`, `__getitem__`, operators
* `dataclasses`, `__slots__`, immutable objects
* `Enum`
* Design patterns — a few basics: Strategy, Factory, Repository, Decorator (as an object)
* SOLID — overview

**Task:** Library model: `Book`, `Member`, `Loan`, `Library`; borrowing with rules (limit, book unavailable), notifications via swappable channels (`Protocol`), dataclasses, Enum for statuses, full tests. **Verification:** adding a new notification channel requires no changes to existing classes; he justifies every inheritance vs composition choice in the code.

## 5. Data structures

* Overview: list, tuple, dict, set, string — what's underneath
* When to pick which
* Big O notation, complexity of operations on each structure
* `collections`: `defaultdict`, `Counter`, `deque`, `namedtuple`
* Stack, queue, linked list — own implementation
* Binary tree, BST, heap (`heapq`)
* Graph: adjacency list, BFS, DFS
* Hash map — how it works, why O(1)
* LRU cache — own implementation

**Task:** Own implementations with tests: stack, queue, linked list, BST, min-heap, graph (BFS/DFS), LRU cache. `timeit` benchmark: `in` on list vs set, `insert(0)` vs `deque.appendleft`, string concatenation vs `join` for n = 10³…10⁶, results as a table in README. **Verification:** he writes LRU cache and BFS from memory in < 15 min and states the complexity of every operation in his structures.

## 6. Algorithms

* Recursion
* Sorting: bubble, merge, quick — understand them; in practice `sorted()` and `key=`
* Binary search, `bisect`
* Two pointers, sliding window
* BFS/DFS on a graph, shortest path

**Task:** ~40 NeetCode problems (Arrays & Hashing, Two Pointers, Sliding Window, Stack, Binary Search, Trees), each in the repo with tests and a complexity comment. **Verification:** you pick 3 solved problems at random, he solves them again live, explaining out loud; merge/quick sort written from scratch and compared against `sorted()`.

## 7. Python — intermediate

* Iterators, generators, `yield`, lazy evaluation
* `itertools`, `functools`

* Context managers (`with`, `contextlib`)
* Pydantic v2: models, validation, serialization
* Logging instead of print
* Testing: mocks, `unittest.mock`, coverage
* Reading: "Fluent Python" (selected chapters)

**Task:** `utils` library: decorators `@timed`, `@retry`, `@memoize`; context managers `Timer`, `atomic_write`; generators `chunked`, `windowed` that work on infinite iterators; Pydantic models with validation (ISBN, email, dates); logging configured from a file. **Verification:** `chunked` on 10⁷ elements doesn't eat memory; tests use mocks to check call counts in `@retry`; coverage ≥ 90%.

## 8. Concurrency

* GIL — what it is and why
* threading vs multiprocessing vs asyncio — when to use which
* `asyncio`: `async/await`, `gather`, semaphore

**Task:** The same program twice: fetching 500 URLs (I/O-bound) and hashing 10⁷ strings (CPU-bound), each sequential / threads / processes / asyncio. Timing table in README. **Verification:** using his own table, he explains the GIL — why threads helped in one case and not the other.

## 9. SQL and databases

* Transactions, ACID, isolation levels
* Python ↔ Postgres: `psycopg`, then SQLAlchemy 2.0 (Core + ORM)
* Migrations: Alembic
* N+1 problem

**Task:** Library schema from ch. 4 in Postgres (foreign keys, constraints, indexes), 15 queries: JOINs, GROUP BY/HAVING, CTE, window function, `EXPLAIN ANALYZE` before and after an index. Python repository with a borrow transaction (all or nothing), Alembic migrations. SQLBolt and pgexercises completed. **Verification:** SQL injection test via book title does no harm; a test proves rollback on an error mid-transaction; he demonstrates N+1 and how he fixed it.
